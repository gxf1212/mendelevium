# JCIM明确数字资源投稿要求：软件开发记录至少六个月，在线服务需保障长期可用

## 本文信息

- **标题**：JCIM的Application Note：化学信息学与分子建模领域数据、软件和网络服务的发表平台
- **文章类型**：Editorial（社论）
- **作者**：Ariane Nunes Alves、Rommie E. Amaro、Yee Siew Choong等15位作者
- **发表期刊**：Journal of Chemical Information and Modeling
- **发表时间**：2026年9月14日
- **DOI**：https://doi.org/10.1021/acs.jcim.6c02729
- **引用格式**：Nunes Alves, A.; Amaro, R. E.; Choong, Y. S.; et al. Application Notes in JCIM: A Home for Data, Software, and Web-Based Services in Cheminformatics and Molecular Modeling. *J. Chem. Inf. Model.* **2026**, *66*, 10447–10449. https://doi.org/10.1021/acs.jcim.6c02729

## 摘要

> 化学信息学与分子建模的快速发展，与高质量数字资源的开发密不可分。经过整理的数据库、基准测试数据集、软件工具、网络服务和集成平台，正日益塑造着化学、生命科学与材料科学领域的研究如何被开展、验证与传播。有鉴于此，《化学信息学与建模杂志》（JCIM）设立了 Application Note 这一稿件类型，作为报道数字资源的专门渠道。在本社论中，我们概述了 JCIM 作为 Application Note 所欢迎的成果类型，并鼓励作者将其视为在化学信息学与分子建模领域传播数字资源的主要渠道。

## 什么成果适合Application Note？

**资源本身必须能供其他研究者访问和使用**。仅有概念设计、仅供内部使用的脚本或工作流程，并不足以构成这类稿件。可以通过实际案例和验证结果展示资源的性能，但文章应把科研价值和可用性说清楚，避免写成产品介绍。

| 成果类型 | 稿件应讲清楚的内容 | 社论列举的已发表资源 |
| --- | --- | --- |
| 数据库与数据资源 | 数据范围与规模、更新策略、格式与标识符、质量控制、获取方式及相较既有资源的差异。 | ToxFCDB、NavDB、PharmGEO。 |
| 基准测试数据集 | 数据来源、纳入标准、清洗与归一化、已知偏差、推荐评估协议及基线结果。 | UNIQUE、AbSet、ThermoPred；还举出AMBER自由能验证框架。 |
| 软件包 | 解决的问题、相较既有工具的算法或方法学进展、示例流程、安装方法、依赖项和支持系统。 | AmberTools、Chemprop、REINVENT 2.0、SuAVE-Scatter。 |
| 网络服务 | 可公开访问的线上功能、输入输出格式、用户操作流程、完整文档及长期维护安排。 | SwissParam、MolGpka、CHARMM-GUI Ligand Docker、PPB3。 |
| 集成平台 | 多个模块如何衔接、完整研究流程、平台架构、组件文档、访问与托管保障。 | Chemistry42、PandaOmics、AI-MedCraft。 |

## 准备投稿时，哪些要求需要提前落实？

| 项目 | 社论中的具体要求 |
| --- | --- |
| 篇幅 | **原则上不超过4000词**，包括摘要、正文和图注，不包括参考文献；充分说明理由并在cover letter中解释后，编辑可允许超出。 |
| 图和标题 | **至少一幅图**；建议在标题中写明资源名称，突出科学、技术或可用性进展。 |
| 桌面或独立软件 | 通过公开代码仓库展示**投稿前至少六个月的活跃开发记录**，并提供社区使用情况指标，如下载统计。 |
| 在线服务 | 投稿时在cover letter中提供正式的可持续性声明，说明有保障的托管支持；配套开源仓库，以便服务下线后社区仍可重新部署或恢复。 |
| 可访问性与许可 | 资源发表时应可供科研群体使用；在可行时遵循FAIR原则（数据应可发现、可访问、可互操作、可重复使用），并提供明确的许可条款。 |
| 同行评审 | 需以不暴露审稿人身份的方式提供资源；审稿人将检查功能、可靠性、可访问性、文档和社区使用价值，以及相关代码和数据。 |

**六个月**这一要求针对桌面或独立运行软件包的开发记录，不能简单理解为所有数据库和网络平台都要在投稿前公开运行六个月。在线服务则有单独的托管声明和可重新部署要求。社论也没有把所有资源的社区下载量规定为某个统一的最低数字。

### 软件文章应该怎样组织内容？

编辑给出的关注点比较实际：先说清楚软件解决了什么问题，相较现有方案有何实质进展，再展示一个能完整运行的使用流程。安装说明、依赖项、支持的操作系统和实际输出也应写得足够明确，**保证审稿人可以评估工具是否真正可用**。

论文发表时，软件在条件允许的情况下应支持跨平台使用，并可供学术和商业用途使用。这属于社论使用“wherever possible”表达的鼓励事项，**不能误写成所有软件都必须无条件允许商业用途**。

对于整合生成模型、性质预测、对接或可视化等功能的平台，重点还包括**模块间的衔接和端到端工作流程**。单纯把多个功能放在一个界面中，仍需要说明整体架构与实际科研使用方式。

## 这篇社论传递了什么变化？

JCIM明确把数字资源的长期可用性放进了投稿与审稿要求。编辑特别提到，**要避免大量生命周期很短的AI生成代码**；因此，软件需要拿出持续开发和实际使用的证据，网络服务则要考虑托管终止后能否由社区恢复。

对于正在准备软件稿的研究团队，**开发记录、说明文档、可运行案例、公开获取方式和维护方案**应当与算法及测试结果一起准备。

> 这是社论明确要求展示的内容，不能只在论文写完后临时补一个代码仓库。

不过，Application Note的设立**并不意味着工具只有工程实现就足够**。社论仍要求解释科学或技术问题，突出相较现有方案的进展，并经受科研价值与资源质量两方面的审查。

社论以此向科研群体发出邀请，希望开发数据库、基准数据集、软件工具、网络服务或集成平台的研究者，考虑以Application Note形式投稿，共同把这一类型建设成化学信息学与分子建模数字成果的核心发表渠道。
